# Протокол повторного эксперимента #11

## Модель и диапазон

Target — **Qwen/Qwen3-8B**, BF16. В [карточке модели](https://huggingface.co/Qwen/Qwen3-8B)
указан нативный контекст **32 768**. Каждая последовательность продолжается до
**49 152 суммарных токенов**, включая исходный промпт: это 1,5× нативной границы.
YaRN выключен, исходный `rope_theta=1000000` сохранён. Через штатный
`hf_overrides` расширен допустимый диапазон позиций обычного RoPE.
`max_position_embeddings=40960` в исходном конфиге не используется как нативная
граница: карточка объясняет эту настройку резервом 8192 входных и 32768 выходных токенов.

| Модель | Закреплённая revision |
| --- | --- |
| `Qwen/Qwen3-8B` | `b968826d9c46dd6066d109eabc6255188de91218` |
| `z-lab/Qwen3-8B-DFlash-b16` | `9b41424b7109f9c5413454f481b09a82b85333f4` |
| `Tengyunw/qwen3_8b_eagle3` | `2a1059d51f622b8cad7d7d72840153ffea5488a0` |

Основные варианты: DFlash с 7 предложенными токенами, EAGLE-3 с 7 токенами
в цепочке и AR без спекуляции. Это обычный EAGLE-3, не EAGLE 3.1.
Дополнительный контроль DFlash использует 15 предложенных токенов — блок 16,
рекомендованный в [карточке драфтера](https://huggingface.co/z-lab/Qwen3-8B-DFlash-b16).
Для него взяты первые 28 исходных промптов, по 7 каждого домена. Его acceptance
сравнивается с теми же 28 начальными промптами основного DFlash; сравнивать
его суммарную скорость со скоростью полной очереди из 200 запросов некорректно.

EAGLE-2 исключён: найденный `Tengyunw/qwen3_8b_eagle2_v0` имеет несовместимое
имя архитектуры и обученный `fc.bias`, отсутствующий в штатной реализации
установленного vLLM. Пользователь попросил не патчить модель и движок.
Ветвящиеся деревья EAGLE-2/3 отложены по его выбору в пользу vLLM.
Неудачные предварительные проверки этих адаптаций сохранены отдельно и не входят в результаты.

## Данные и генерация

Использованы те же 200 исходных сообщений, что в предыдущем эксперименте,
с новой токенизацией для Qwen3-8B:

- 50 задач MATH-500, `test`;
- 50 функций HumanEval, `test`;
- 50 диалогов UltraChat, `test_sft`, история до второго пользовательского сообщения;
- 50 примеров BBH: по 5 из десяти задач на неарифметическое рассуждение.

Источники, revisions, source IDs, сообщения и token IDs сохранены в
[JSONL](../../data/long_context_qwen3_8b_prompts.jsonl), хеш набора — в
[manifest](../../data/long_context_qwen3_8b_prompts.manifest.json).
Домены перемежаются в очереди. Разделение чатов и математики/кода основано
на эвристическом фильтре, а не на доказанном отсутствии пересечений.

Начальные промпты короткие: **21–1221 токен**. Длинный префикс образуется
собственной генерацией модели. Это не бенчмарк понимания входных документов
длиной 32K и не набор реальных длинных агентных трейсов. Каждый метод получает
одинаковые начальные token IDs, но генерирует собственную траекторию;
совпадение greedy-продолжений между методами не предполагается.

По завершении полные выходные token IDs DFlash k=7 и EAGLE-3 k=7 совпали
в 197 из 200 пар. Этот поднабор дополнительно разобран отдельно. С AR
ни одно полное продолжение не совпало; между DFlash k=7 и k=15 также нет
полных совпадений на 28 контрольных промптах. Причина расхождений с AR
отдельно не изолирована.

`temperature=0`, `top_p=1`, thinking включён, `ignore_eos=True`. Два EOS
(`151643`, `151645`) запрещены штатным `SamplingParams.bad_words`.
Target выбирает наиболее вероятный разрешённый токен и применяет запрет при
верификации. Когда top-1 — EOS, это даёт следующий разрешённый токен;
если top-2 — другой EOS, он тоже пропускается.

Драфтер не изменён и может предлагать EOS, который target отвергнет.
Поэтому это измерение при изменённой политике target, а не при естественной
остановке. В V2-логе vLLM реальные draft IDs недоступны: scheduler видит
заглушки `-1`. Выделить долю отказов именно из-за предложенного EOS по этим
логам нельзя. Счётчики accepted/proposed доступны из штатного учёта vLLM.

## Исполнение и измерения

Две NVIDIA B300 по 275040 MiB работают независимо, **TP=1** на каждой.
GPU 2 выполняет основной DFlash и затем контроль k=15; GPU 3 — EAGLE-3
и затем AR. Везде continuous batching с максимумом **28** активных запросов,
async scheduler, `max_num_batched_tokens=4096`, `gpu_memory_utilization=0.92`,
prefix caching выключен. При завершении запроса его место сразу занимает следующий.

Версии: vLLM 0.32.0, PyTorch 2.13.0+cu130, Transformers 5.19.0.
Код инференса закреплён коммитом `517eb0a4790884c6959ad210134aba2e79aedf6f`
в отдельном checkout. Наблюдающий scheduler записывает штатные счётчики,
не меняя решений планировщика. Установленный код vLLM, модели и веса
не патчились. `metadata.git_dirty=true` объясняется только незакоммиченным
симлинком `.venv`; совпадение исходников с коммитом проверяется отдельно.

Перед полными прогонами выполнены короткие проверки всех трёх методов
и заполнения KV-кеша 28 одновременными последовательностями около 49 152.
Искусственные длинные входы этой проверки не включены в исследовательские графики.

- Acceptance — `accepted / proposed`, без бонусного target-токена.
- Accepted per round — принятые draft-токены на раунд проверки.
- Для каждого промпта считаются суммы в интервалах по **2048** токенов
  префикса перед раундом; затем усредняются отношения с одинаковым весом промптов.
- Графики показывают 95% bootstrap-интервалы по промптам, 500 перевыборок.
  Парные изменения между окнами 4–8 Ki и 44–48 Ki, а также 28–32 Ki и 32–36 Ki
  используют 2000 перевыборок. Это не доверительный интервал по повторным GPU-прогонам.
- Суммарные ток/с — все выданные токены / время всей очереди после загрузки
  модели, включая заполнение и опустошение батча, prefill и накладные расходы логирования.
- График скорости по префиксу использует время между поступлениями выходных
  токенов каждого запроса. Парность означает одинаковый исходный prompt ID,
  а не одинаковый сгенерированный текст или состав соседей по батчу.

## Аудит повторений и границы выводов

Запрет EOS не запрещает повторение обычного текста. В [карточке Qwen3](https://huggingface.co/Qwen/Qwen3-8B#best-practices) отдельно
предупреждают о риске бесконечных повторений при greedy thinking.
Для каждого интервала проверяются последние 2048 сгенерированных токенов:
периоды 1–128, цикл отмечается при совпадении с лагом не менее 99%.
Дополнительно считаются точные циклы и фактически выданные EOS.

Для конечных хвостов, пропущенных этим детектором, выполнена дополнительная
проверка: последние 8192 токена, периоды 129–2048, тот же порог совпадения 99%.
Она применяется только к конечным хвостам и записывается в `long_tail_audit.csv`
и `control_long_tail_audit.json`; классификация интервалов на графиках остаётся
исходной, с периодами до 128.

График без обнаруженных коротких циклов использует меньше наблюдений,
меняющийся состав промптов и не доказывает осмысленность оставшегося текста.
Повторение длинных функций или абзацев этот детектор может пропустить.
Домен обозначает источник исходного запроса, а не гарантированный тип позднего хвоста.

Здесь измеряется поведение конкретных чекпойнтов при принудительном продолжении.
Из различия кривых нельзя отдельно установить влияние длины, повторений,
запрета EOS, обучающей смеси, бюджета драфта и расхождений траекторий.
Для причинного сравнения нужен следующий эксперимент на одинаковых фиксированных
длинных префиксах с осмысленным содержимым и отдельным контролем EOS-политики.
